Pseudocode
function mergeSort(arr, l, r): if l >= r: return mid = (l + r) / 2 mergeSort(arr, l, mid) // sort left mergeSort(arr, mid+1, r) // sort right merge(arr, l, mid, r) // merge halves function merge(arr, l, mid, r): // compare and combine sorted subarrays
Complexity
TimeO(n log n) always, no worst case. Splitting costs O(log n) levels; merging costs O(n) per level.
SpaceO(n), requires an auxiliary array for the merge step. Not in-place.
Key Insights
  • Core ideaSplitting is trivial, all the real work happens in the merge step. Two sorted arrays can be merged in O(n) by comparing front elements one at a time.
  • When to useWhen stability matters (equal elements keep original order), or when sorting data on disk (external merge sort). Guaranteed O(n log n) unlike quicksort.
  • Watch outRequires O(n) extra memory. For in-place sorting where memory is constrained, quicksort is preferred despite its worst-case risk.
