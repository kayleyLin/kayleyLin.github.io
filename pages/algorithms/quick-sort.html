Pseudocode
function quickSort(arr, low, high): if low < high: pivot_idx = partition(arr, low, high) quickSort(arr, low, pivot_idx - 1) quickSort(arr, pivot_idx + 1, high) function partition(arr, low, high): pivot = arr[high]; i = low - 1 for j in [low..high-1]: if arr[j] <= pivot: i++; swap(arr[i], arr[j]) swap(arr[i+1], arr[high]); return i+1
Complexity
TimeO(n log n) average, O(n²) worst case when pivot is always the min or max
SpaceO(log n) average stack depth, O(n) worst case (skewed recursion)
Key Insights
  • Core ideaPivot selection determines everything. A good pivot splits the array roughly in half each time, giving O(log n) levels. A bad pivot (always min/max) gives O(n) levels.
  • When to useDefault choice for in-memory sorting. In practice faster than merge sort due to better cache performance and no extra memory allocation.
  • Watch outSorted input + first-element pivot = O(n²) every time. Production implementations always use randomised pivot or median-of-three to avoid this.
