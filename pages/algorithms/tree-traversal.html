Pseudocode
// Pre-order: Root → Left → Right visit(node) traverse(node.left); traverse(node.right) // In-order: Left → Root → Right traverse(node.left) visit(node); traverse(node.right) // Post-order: Left → Right → Root traverse(node.left); traverse(node.right) visit(node)

Complexity
TimeO(n) for all three orders, every node visited exactly once, no revisits
SpaceO(h) recursion stack, O(log n) balanced, O(n) skewed tree
Key Insights
  • Core ideaThree orders, one rule change: where you "visit" (process) relative to recursing left and right. Pre = Root first. In = Root middle. Post = Root last.
  • When to usePre-order: copying/serialising trees. In-order: iterating a BST in sorted order. Post-order: safe deletion (children before parent), evaluating expression trees.
  • Watch outIn-order only produces sorted output for BST, not for arbitrary binary trees. Confusing the three orders is a classic interview mistake; remember the Root's position in the name.
